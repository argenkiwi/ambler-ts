walks/chat.ts saves the next nodeId and state to a Pi document (ambler.chat-checkpoint, conversation scope) after every amble() step; nodes are unchanged because durability is injected via the loop and the chat Utils seam in response.ts. Quitting maps CHAT_BYE to CHAT_PROMPT so relaunching continues the conversation. On resume, an unreachable saved host restarts at LLM_CHECK instead. Deno prompt() returns null on non-TTY stdin, so scripted e2e runs need a pty (macOS: script -q /dev/null).
