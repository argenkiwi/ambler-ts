ambler node/walk must produce files that pass the target project's biome check and tsc unchanged (walks/tests/scaffold-output.test.ts scaffolds into a temp project and enforces it). String templates cannot get line wrapping and Biome's natural import order (a9 before a10) right in general, so ScaffoldUtils.format runs node_modules/.bin/biome check --write on just the written files (no-op without Biome); templates still aim to be formatted. Empty State is no longer an empty interface with a biome-ignore: a node with no state, and a walk whose nodes have none, render `export type State = object;` (Record<string, never> would reject any walk State with fields, since S extends NS); a node with state renders `interface State extends HasA, HasB {}`, which Biome's noEmptyInterface accepts because it extends something. A scaffolded util's Utils is `type XUtils = Record<string, never>` for the same reason. `--state field` and `ambler walk` read nodes/state.ts and node files through utils/node-source.ts, a deliberately small regex/bracket reader (TypeScript 7 is native, no JS compiler API) good enough for Biome-formatted files. Unwired walk edges use a local unexported `unwired(id): never` that throws inside the lazy factory thunk, so the walk type-checks but fails only when that node is reached; walk-surface allows only the four exports.
