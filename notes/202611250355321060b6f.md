ambler node/walk must produce files that pass the target project's biome check and tsc unchanged (walks/tests/scaffold-output.test.ts scaffolds into a temp project and enforces it). String templates cannot get line wrapping and Biome's natural import order (a9 before a10) right in general, so ScaffoldUtils.format runs node_modules/.bin/biome check --write on just the written files (no-op without Biome); templates still aim to be formatted. Empty interfaces use a biome-ignore noEmptyInterface comment rather than Record<string, never>, because a node State of Record<string, never> rejects any walk State with fields (S extends NS). `--state field` and `ambler walk` read existing nodes through utils/node-source.ts, a deliberately small regex/bracket reader (TypeScript 7 is native, no JS compiler API) good enough for Biome-formatted node files. Unwired walk edges use a local unexported `unwired(id): never` that throws inside the lazy factory thunk, so the walk type-checks but fails only when that node is reached; walk-surface allows only the four exports.
