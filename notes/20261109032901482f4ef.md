utils/durable.ts submits each chat turn to Pi with requestId turn-<messages.length>; a repeated requestId returns the existing submission, so a crash mid-response (verified with kill -9 against real Ollama) never calls the model twice. Pi owns the transcript, so only the last user message is sent and the Ambler messages array is just a mirror. Gotcha: a failed turn stays unanswered under the same requestId forever, so chat() checks submission.status() and submits a continue with requestId turn-<n>-retry-<k> instead of re-adding the user message. Set settings.retry.maxRetries to 1, as the default backoff made a down host take ~14s to fail.
