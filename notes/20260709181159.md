The Zettelkasten-RAG walk, its 8 nodes, 3 utils, tests, and specs were renamed from `zettel`/`Zettel*` to `azk`/`Azk*` throughout: files (walks/azk.ts, nodes/azk-*.ts, utils/azk_*.ts, specs/azk.md), the deno.json task, the SQLite table names (zettels/zettels_fts -> azk/azk_fts), interfaces/functions (ZettelMeta/ZettelLink/upsertZettel/etc -> Azk-prefixed), and the on-disk storage path (.zettelkasten/zettel.db -> .azk/azk.db). Generic prose/variable mentions of a single note ("a zettel", "the zettel's id") were changed to "note" instead of "azk", since AZK is being treated as the product/CLI brand name, not a replacement for the domain noun -- the existing `Note`/`NoteLink` types already covered that concept. `Zettelkasten` as the methodology name is kept as-is in prose (e.g. "Zettelkasten RAG Protocol", "Zettelkasten-RAG" section headers) -- only the CLI/brand name changed, not the underlying method's name.

The skill surface was also consolidated from ambler-zettel-init + ambler-zettel + an unfinished top-level zettel/ install doc into exactly two self-contained skills: azk-install (global, project-independent: `deno install --global` + merges the protocol into the agent's own global instructions file -- no project files touched, since azk lazily creates notes/ and .azk/ on first use) and azk-init (per-project, Ambler-specific: vendors the walk's code via `deno task clone`, writes a local AGENTS.md, and copies itself into the target project's .agents/skills/ so the skill travels with the code). Historical notes/*.md entries and the one-off scripts/migrate-zettel-to-markdown.ts were deliberately left referencing the old name -- they're historical record, not live documentation.
