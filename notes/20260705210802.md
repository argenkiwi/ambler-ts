nodes/zettel-search.ts always runs FTS5 keyword search first (zero setup, always available). If a local OpenAI-compatible embeddings host is reachable (default http://localhost:11434/v1, model nomic-embed-text, same convention as utils/llm_chat.ts), it also embeds the query and computes cosine similarity against every stored embedding. This is additive, not just a re-rank of keyword hits: a note with zero keyword overlap but high semantic similarity can still surface in results, because semantic matches not already in the keyword candidate set get fetched via getZettel and added. utils/embeddings.ts embed() never throws on an unreachable host -- it catches and returns null, matching utils/llm_chat.ts checkHost()s soft-fail style -- so search silently degrades to keyword-only when no embedding model is running.
