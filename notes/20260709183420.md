After the zettel->azk rebrand (see linked note), the two skills that shipped in the same PR already had bugs discoverable just by diffing their prose against the actual code -- worth remembering as a class of bug (fresh skills going stale relative to the code they document within the same day), not just the specific fixes:

1. azk-install Step 2 used `deno install --global` without `-f`/`--force`. Deno refuses to overwrite an existing global install without it, so re-running the skill after any ambler-ts change (its entire purpose) fails with "Existing installation found". Fixed by adding --force -- safe here because this install is meant to be idempotent/rerunnable by design.

2. azk-install Step 3 told the agent to search for a "## Zettelkasten RAG Protocol" (H2) heading to decide whether to replace-vs-append into the agent's global instructions file, but the asset it merges in is actually H1 ("# Zettelkasten RAG Protocol"). A literal heading-level match would miss real installs and duplicate the section. Fixed by matching on heading text only, not level, in both azk-install and azk-init (the latter's asset happens to be H2 already since it nests inside a project AGENTS.md, but the same robustness applies if someone hand-nests it differently).

3. Both skills' assets/AGENTS.md, plus the project's own root AGENTS.md, still said the embeddings default model is `nomic-embed-text`, but utils/embeddings.ts (commit be6ea7d) changed the default to `embeddinggemma:latest` and made both host and model overridable via EMBEDDING_HOST/EMBEDDING_MODEL env vars -- neither skill mentioned the env override existed at all.

4. azk-install Step 4's verify command (`azk reindex && azk search "test"`) claimed notes/ and .azk/ both spring up, but confirmed by actually running it: reindex/search alone only create .azk/ -- notes/ is lazily created by azk_fs.ts only on the first actual `create` call. The claim was untested prose, not a bug in the code. Fixed by adding a real `create` call to the verify step so it actually exercises what it claims to prove.

All four were caught by literally running the install end-to-end (not just reading the prose) and grep-diffing skill text against current source (utils/embeddings.ts, deno install --help, nodes/azk_fs.ts). This also fixed live drift on this machine: the global binary was still literally named `zettel` (pre-rebrand) and ~/.claude/CLAUDE.md still documented the zettel command -- now both point at azk.
