devenv.nix gives the host Deno plus a `pi` script that runs @earendil-works/pi-coding-agent (the old @mariozechner package is deprecated) inside the `ambler-pi` image from sandbox/. This is because pi runs tools without asking. Only the repo is mounted, at /workspace. Ollama (qwen3.8:27b-mlx) is reached via host.docker.internal:11434; this works because host Ollama listens on *:11434. Gotchas: (1) pi 1.x trust-gates project .pi/settings.json, so the default model goes in agent-dir settings.json baked into the image, not in the repo. (2) compat is auto-detected from the baseUrl, and host.docker.internal isn't recognised as Ollama, so supportsDeveloperRole:false is set explicitly; reasoning_effort works with Ollama. (3) The bind mount is owned by the host user, so the image sets git safe.directory=/workspace. (4) sandbox-build passes the host Deno version as a build arg so both Denos match. (5) azk is a macOS binary and isn't available inside the container.
