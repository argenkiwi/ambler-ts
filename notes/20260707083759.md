Reworked storage so notes persist as notes/<id>.md (YAML frontmatter + body, Obsidian/HelixNotes-compatible) and are version-controlled; .zettelkasten/zettel.db became a derived, gitignored SQLite cache (FTS5 + embeddings + link graph) that any zettel-* command can rebuild from scratch via a new `zettel reindex` subcommand. Key decisions: (1) filename is <id>.md only, never a title slug, so renaming a title never touches the filename or git history -- links reference ids, not paths. (2) A note stores only its own outgoing links in frontmatter (links: [{to, relation}]); backlinks are computed from the index, never written into the target notes file, so linking never mutates a second file. (3) The zettels SQLite table dropped its body column entirely -- the file is authoritative for body, and zettels_fts still keeps its own mirrored copy for FTS5 matching (inherent to a shadow FTS table, not new duplication). (4) Reindex staleness detection uses a SHA-256 body_hash column so unchanged notes are never re-embedded on a bulk rebuild. (5) DatabaseSync does not create its parent directory -- open() must Deno.mkdirSync(dir, {recursive:true}) before opening, a bug that was latent for months because .zettelkasten/ was never deleted until reindex made a from-scratch rebuild a normal operation; caught by the ship end-to-end test (rm -rf .zettelkasten && zettel reindex). Migration of this repos own pre-existing DB-only notes ran via a one-off scripts/migrate-zettel-to-markdown.ts that reads the OLD schema directly with a raw DatabaseSync (bypassing utils/zettel_db.ts, which now assumes the NEW schema and would silently skip recreating an existing old-schema table).
