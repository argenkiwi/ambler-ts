ambler-ts adopted the cross-language state convention: every field has one `export interface Has<Field> { field: T }` in the registry nodes/state.ts; a node exports `interface State extends HasA, HasB {}` (imported from ./state.ts) or `type State = object`, and never declares fields itself. The registry is the single source of a field's type, so `node --state f` resolves only through it (bare f without HasF, or f:T conflicting with HasF, exit 2; a new f:T is appended, merging into an existing `import type` from the same module) and `walk` builds its concrete State from the contracts the nodes extend, exiting 2 on an unknown Has* or on a node with own State fields rather than silently ignoring them (the gap ambler-py had). The walk's State stays a concrete interface with fields, not `extends Has*`, so its initial state and any walk-only typing remain explicit. `check` enforces it as the `state-contracts` rule (utils/conventions.ts), per file: Has* only in nodes/state.ts with exactly one member named after it; files directly in nodes/ (not tests, not state.ts) must export State in one of the two allowed forms. Gotcha: a field type exported only by state.ts must still be imported by the generated test (`{} as T` mocks), so the registry counts as a type exporter. Message (the chat type) stayed in nodes/prompt.ts and state.ts imports it; a type-only import cycle is fine.
