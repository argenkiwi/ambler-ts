Superseded: notes now live as Markdown files with YAML frontmatter under notes/ (source of truth, version-controlled), and .zettelkasten/zettel.db became a derived, gitignored SQLite index rebuildable at any time via `zettel reindex`. The original tradeoff analysis (one transactional store is simpler than syncing a file + a derived index) held while the DB was the only consumer, but it stopped being the right tradeoff once notes needed to be shareable across machines, reviewable in a PR, and editable in tools like Obsidian/HelixNotes -- a gitignored binary SQLite file cant do any of that. See the note on the hybrid Markdown+SQLite redesign for the new approach and how sync is kept manageable (reindex is idempotent and content-hash-gated, so drift self-heals).
